# 2026-08-07 — Theme switcher, Insights tab, pre-order reminders

necessary. The app gained a proper **Light / Dark / System** setting and a

## What Changed

### 1. Light / Dark / System setting — and a dark mode bug fixed

The app already had a dark colour scheme built in, and it was already being
used: without anyone asking for it, the app quietly followed whatever the phone
was set to. But there was no way to control it, and — more importantly — about
sixty-five colours in the app were fixed to their light-mode values. On a dark
phone those colours stayed bright and washed out, so anyone using dark mode was
already seeing a half-broken app without it ever being a deliberate choice.

Both halves are now fixed:

- A **Light / Dark / System** choice was added, and it is remembered between
  launches. The saved choice is loaded before the app draws its first screen, so
  it does not flash the wrong colours on startup.
- Every status colour (Owned, Ready, Partial, Pre-order, Unpaid, Chase, Case)
  and every dashboard tile colour now has a proper dark version that stays
  readable on a dark background. Light mode is unchanged.

The Owned / Ready / Partial colour list had been copied word-for-word into two
different screens. Both now read from one shared list, so they cannot drift
apart again.

Two things were deliberately **not** changed: the black background behind the
camera scanner, and the badges that sit on top of product photos. Those are
meant to be dark in both themes.

### 2. New Settings screen

There was no settings screen at all before. The gear icon in the top-right of
the Home dashboard now opens one, containing:

- **Appearance** — the Light / Dark / System choice.
- **Pre-order reminders** — the switches described below.
- **Account** — the signed-in email address, and Sign out (moved here from the
  Home dashboard, where it used to sit as a bare icon).
- **About** — the app name and version.

### 3. New Insights tab

A fifth tab at the bottom of the app, showing where the money goes:

- **This month** compared with last month, including whether spending is up or
  down and by how much.
- **Last 6 months** as a row of bars, so a busy month stands out at a glance.
- **Top brands** and **Top shops** — the five biggest by spend, with the number
  of units bought from each.
- **Collection facts** — total collection value, everything paid all-time,
  average price per unit and per model, and how many chase units are owned.

This is all worked out from purchases that are already recorded — no new
information has to be entered, and nothing changed in the database. Spending is
counted from the date a purchase was actually paid, which is the same date the
dashboard already uses.

Adding a fifth tab also meant tidying the bottom menu's internals. The Scan
button is not a real tab (it opens the camera and comes back), and the old code
worked around that with hard-coded position numbers that would have broken as
soon as anything was added. That is now handled properly.

### 4. Pre-order reminders

The app can now send a reminder about a pre-order. There are four kinds:

- **Ready to collect** — once an order is marked ready and not yet picked up.
- **Pickup deadline** — three days before the deadline, and again on the day.
- **ETA reached** — when an order's expected date passes and it still is not
  ready.
- **Payment outstanding** — when an order is ready but not fully paid.

All reminders arrive at 9am rather than at midnight. If something is already
overdue when the app opens, it gives one nudge the next morning rather than
firing immediately — and anything more than three months stale is dropped, since
by then a reminder is just noise.

In Settings there is a master switch plus one switch per reminder type. The
permission request appears when the master switch is turned on, not when the app
first launches, so the ask has some context. If notifications were previously
refused at the iPhone level, the app says so plainly instead of silently doing
nothing.

**One important limit, stated up front:** these reminders are worked out and
scheduled on the phone itself. They arrive reliably once scheduled, but they can
only be recalculated while the app is running. If a pre-order is updated on the
web admin and the phone never opens the app, nothing gets rescheduled. The
Settings screen says this in plain words so it is not a surprise. Proper
server-sent notifications would be a much bigger piece of work.

To keep reminders correct, the whole set is rebuilt whenever the app comes back
to the foreground and after every pre-order status change. Each reminder has a
fixed identity, so rebuilding replaces the old one instead of stacking a
duplicate next to it.

### 5. Tests

Twenty-nine new automated tests were added covering the Insights calculations
(month splits, the year boundary, brand and shop rollups, empty collections) and
the reminder rules (when each kind fires, what gets skipped, and that reminders
do not duplicate). The full suite is fifty tests and all pass.

## User Impact

- The app can be set to Light, Dark, or follow the phone — and it remembers.
- Anyone already using their phone in dark mode gets a properly dark app instead
  of one with washed-out, hard-to-read status colours.
- A new Insights tab answers "how much am I spending, and where does it go"
  without opening the web admin or a spreadsheet.
- Pre-orders that are ready, nearly due for pickup, or still unpaid now come to
  you, instead of needing the tracker to be checked manually.
- Sign out and app info now live in a normal Settings screen rather than as a
  lone icon on the dashboard.

## Notes for Next Time

- **Not yet seen on a device.** The code passes analysis and all fifty tests,
  but it has not been run on the iOS Simulator. The Mac's Xcode selection needs
  fixing first — `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
  (needs the Mac password). After that, worth walking every screen in dark mode
  and checking the reminders actually get scheduled.
- The app's startup splash screen and icon backgrounds are dark navy
  (`#000816` / `#0B1622`). Someone using Light mode now gets a dark splash
  landing on a light app. Not urgent, but it would look better matched.
- Reminders are local-only, as described above. If they turn out to be genuinely
  useful, the next step would be server-sent notifications so a change made on
  the web reaches the phone without the app being opened.
- The "Add Purchase" screen is still hidden behind its off switch
  (`kEnableMobileAddPurchase`) — unchanged today, and still a quick win whenever
  adding purchases from the phone is wanted.
