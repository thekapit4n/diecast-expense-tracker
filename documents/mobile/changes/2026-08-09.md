# 2026-08-09 — HugeIcons, tappable dashboard, Insights charts, Scanner rewrite

## Quick Overview

Replaced the Material icons in the bottom navigation bar and on the Home
dashboard's stat cards with icons from **HugeIcons** (stroke-rounded style),
so the app has one consistent icon look instead of mixing in the default
Flutter/Material icon set.

Files touched:

- `mobile/lib/features/shell/main_shell.dart`
- `mobile/lib/features/home/home_screen.dart`
- `mobile/lib/core/icons/huge_scan_search_icon.dart` (new)
- `mobile/pubspec.yaml`, `mobile/pubspec.lock` (added the `hugeicons` package)

## What Changed

### 1. Bottom navigation bar icons

All five tabs now use HugeIcons instead of Material icons:

- **Home** → Home-01
- **Catalog** → Grid View
- **Scan** → Scan-Search
- **Pre-orders** → Package Process
- **Insights** → Chart Analysis

Most of these come straight from the official `hugeicons` Flutter package,
which ships a free set of about 5,100 stroke-rounded icons. The Scan tab's
icon (Scan-Search) is not in that free set, even though it is marked free on
the HugeIcons website — so it was rebuilt by hand as a small custom-drawn
widget, using the real path data from the icon's downloaded SVG file. It
looks identical to the original; it just is not pulled from the package.

### 2. Home dashboard stat card icons

The five summary cards at the top of the Home tab were also switched over:

- **Models owned** → Car Parking
- **Units owned** → Garage
- **Active pre-orders** → Package Process (now matches the Pre-orders tab
  icon, so the same status reads as the same icon everywhere in the app)
- **Ready to collect** → Package Delivered
- **Unpaid / partially paid orders** → Transaction

### 3. Added the `hugeicons` package, and a Pods hiccup along the way

`hugeicons: ^1.1.7` was added to `pubspec.yaml`. After running `flutter
clean` and `flutter pub get` for the new dependency, Xcode's build briefly
failed with "Unable to load contents of file list" errors for the Release
configuration — the CocoaPods project files had gone stale and needed
regenerating. Running `pod install` again (with `LANG=en_US.UTF-8`, since
CocoaPods on this Mac needs that set explicitly or it crashes) fixed it, and
the build went through afterwards.

### 4. Insights tab — real animated charts

- The "Last 6 months" trend and the "Top brands" / "Top shops" breakdowns
  used to be plain bars drawn by hand, jumping straight to their final size
  with no animation.
- Both are now drawn with the `fl_chart` charting package instead. Bars grow
  in from zero the first time the screen loads, and animate smoothly between
  old and new values whenever the data refreshes (pull-to-refresh, or coming
  back to the tab). Tap a bar to see its exact amount (and, for brands/shops,
  the unit count) in a small popup — that number used to sit printed next to
  the bar at all times, but a real chart doesn't have room for that alongside
  the bar itself, so it moved into the tap.
- The "This month" figure and the money facts at the bottom (collection
  value, total paid, average per unit/model) now count up smoothly to their
  value instead of appearing instantly.
- Loading, empty, and loaded states now cross-fade into each other instead of
  popping.

### 5. Dashboard cards you can tap

- **Models owned**, **Ready to collect**, and **Unpaid / partially paid
  orders** are now tappable — each jumps straight to the right tab with a
  filter already applied (Catalog → Owned; Pre-order Tracker → Ready tab;
  Pre-order Tracker → a new "Unpaid only" filter). A small arrow (`›`) now
  shows on the right edge of any card that does something, so it's obvious
  at a glance which of the five cards are tappable and which aren't (before
  this, none of them looked any different from each other).
- The "Unpaid only" filter is also available as a manual toggle chip on the
  Pre-order Tracker itself, not just via the dashboard card.
- One known limitation: the Home dashboard's "Unpaid" count includes every
  unpaid purchase in the app, but the Pre-order Tracker only ever lists items
  linked to a tracked PO order — so the number on the card and what you see
  after tapping it won't always match exactly. A fully accurate version would
  need a new "all purchases" list screen, which felt out of scope for now.

### 6. Smart Image Scanner — rewritten from barcode-first to text-first (Phase 1)

The trigger for this: scanning a box in a shop kept locking onto the barcode
instead of reading the item number/model text next to it — and the app
doesn't even store barcode values, so a detected barcode could never actually
match anything in the catalog.

- Removed the old live barcode-hunting camera (the `mobile_scanner` package)
  entirely, along with the barcode search path that fed a scanned barcode
  number into catalog matching as if it were an item number.
- OCR now reads the *whole* box, not just a barcode. Any run of digits shaped
  like a real barcode (8, 12, 13, or 14 digits — the standard barcode
  lengths) gets filtered out of the text before matching, whether it's
  written together or with the usual OCR-introduced spaces/hyphens. Only the
  barcode number is dropped — other text on the same line survives.
- Matching itself was rewritten to check the real catalog instead of two
  hardcoded regex patterns. An exact match against a catalog item's real
  item number wins outright; a "close but not quite" OCR misread (one or two
  character difference, depending on code length) is accepted as a weaker
  fuzzy match; brand name and model name matter as a fallback when no item
  number is readable at all. Results are now labelled **Exact / Likely /
  Possible** instead of one flat list, and each result shows *why* it
  matched (e.g. "Item number MGT00012" or "Brand Mini GT").
- The "you already own this" warning only appears automatically for an
  *exact* match now — a merely "possible" guess used to be enough to trigger
  it, which was misleading.
- Chase and normal variants that share the same item number both show up
  side by side for you to pick, instead of one being silently hidden.
- Added 12 new automated tests covering barcode filtering at every standard
  length, OCR-mistake tolerance, the chase/normal case, and the "no false
  matches from generic packaging text" case.

### 7. Scan screen — full-screen live camera, WhatsApp/Instagram-style

- The Scan tab used to open a full native OS camera screen (with no way to
  reach the gallery from inside it), or before that a two-button "Take
  photo" / "Choose from gallery" chooser screen.
- It's now a proper live camera view built into the app: a real-time preview
  fills the whole screen, with a shutter button and a gallery button sitting
  together at the bottom, plus a flash/torch toggle for dim shops — the same
  layout style as WhatsApp, Instagram, or Shopee's camera screens. You can
  switch to the gallery at any moment without leaving the camera.
- Scan is now a normal tab like the other four (Home, Catalog, Pre-orders,
  Insights) — it used to open as a separate full-screen page that hid the
  bottom navigation bar entirely. The bottom nav now stays visible the whole
  time you're scanning.
- Because a live camera is a real hardware resource (unlike the old
  photo-picker approach), the app now explicitly turns it on only while the
  Scan tab is the one on screen, and turns it off the moment you switch to
  another tab or the app goes to the background — otherwise it would keep
  running invisibly and draining battery.
- Added the `camera` package. On iOS this project resolves plugins through
  Swift Package Manager rather than CocoaPods, so — unlike the `hugeicons`
  Pods hiccup above — nothing needed running for this one; Xcode fetches it
  automatically on the next build (needs network access the first time).
  `NSMicrophoneUsageDescription` was added to `Info.plist`, which the
  `camera` plugin requires even though this app never records audio.
