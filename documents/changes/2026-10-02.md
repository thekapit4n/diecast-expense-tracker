# Changes Log - 2026-10-02

This note records all work done today in simple language.

## Quick Overview

- Mini GT set and special releases have item numbers like **MGTS0026**: a letter where regular releases have a digit. Most of the app only accepted the regular `MGT00009` shape, so these items were rejected or handled wrongly.
- The app now has one shared rule for Mini GT item numbers. It accepts both shapes, and every screen and image route uses it.
- Web files touched: `lib/collection-images.ts`, `app/api/management/mini-gt-import/route.ts`, `app/api/catalog/image/[...path]/route.ts`, `app/api/mini-gt/image/[series]/[fileName]/route.ts`, `app/management/image-import/page.tsx`, `components/purchase/edit-purchase-modal.tsx`.
- Mobile files touched: `mobile/lib/data/catalog_image_paths.dart`, `mobile/lib/features/scan/scan_matching.dart`.

## What Changed

### 1) Mini GT set item numbers (MGTS0026) now accepted

- The check was "MGT followed by exactly five digits". `MGTS0026` has an **S** in the fourth position, so it failed.
- That check was copied into several places, so one item number broke several things:
  - **Image Import → Mini GT Import From Product URL** refused it with "Series must be like MGT00009".
  - **Image Import → Upload Collection Images** didn't recognise it as an item number. It used the model name as the storage folder (e.g. `mini-gt/LAMBORGHINI-HURAC-N-STERRATO-...`) instead of `mini-gt/MGTS0026`.
  - **Catalog** couldn't find images for these items, because the image routes and the "does this car have photos" check used the same rule.
  - **Edit Purchase** couldn't pick the series out of the item number to offer the Mini GT import.
- Now there is one rule in `lib/collection-images.ts`: **MGT + one letter or digit + four digits**, so 8 characters in total. It accepts `MGT00009` and `MGTS0026`, and still rejects junk like `MGT0009` or `MGTSS026`.
- Two helpers are shared everywhere: `isMiniGtSeries()` checks a whole value, and `extractMiniGtSeries()` finds the series inside a longer item number.
- The error message and the help text on the import page now mention both formats.
- The mobile app uses the same rule to build image paths, so MGTS photos show on the phone too. The scan screen's "detected item no" hint also recognises the letter form.

## User Impact

- You can import and upload photos for Mini GT sets like **MGTS0026** the same way as regular releases.
- Their photos are stored under the item number and show up in the Catalog on web and mobile.

## Notes for Next Time

- Any MGTS photos uploaded **before** this fix are stored in a folder named after the model, not the item number. Either upload them again or move them into `mini-gt/<item number>/` in Supabase Storage, otherwise the Catalog won't find them.
- If Mini GT starts using another item number shape, change the pattern in `lib/collection-images.ts` and in `mobile/lib/data/catalog_image_paths.dart`. Nothing else should need touching.
