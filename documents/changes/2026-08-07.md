## What Changed

### 1) Light / Dark / System theme switcher

- The portal has always been dark. The dark navy colours were written straight into the base stylesheet, and there was no light version at all.
- Added a proper theme switcher with three choices: **Light**, **Dark**, and **System** (follow whatever the computer is set to).
- The switch lives in the bottom-left of the navigation, just above the Logout button. It shows on desktop in the sidebar, in the collapsed narrow sidebar, and in the slide-out menu on phones — one control, everywhere.
- The Settings page also gained an **Appearance** card at the top with the same choice, so it can be found there too. It applies straight away — no Save button.
- The choice is remembered between visits. Someone who never touches it keeps seeing the dark portal exactly as before.

**Why it was built the unusual way.** Normally a site like this treats light as the "base" look and layers dark on top. This one was built the other way round from the start, and switching it over would have quietly changed the appearance of about fifteen files' worth of buttons, inputs, checkboxes, tabs and dropdowns all at once. So light was added as an extra layer on top of the existing dark instead. The practical result: the dark portal looks exactly as it did yesterday, and light is purely a new addition. This is deliberate and should not be "tidied up" later without redoing those fifteen files at the same time.

### 2) Light colours chosen for readability, not just inverted

- A few of the dark theme's colours cannot simply be reused on a white page — the bright teal and the "owned" green are too pale to read against white. The light theme uses deeper versions of the same colours instead, so the portal still looks like itself.
- The big data tables (purchases, collection, brands, shops) needed their own pass. Their icons were being colour-flipped to show up against dark navy; that flip is now switched off in light mode, otherwise every icon would have come out inverted and unreadable.

### 3) Colours moved into one place

- The file that holds the portal's colours (`lib/theme/diecast-theme.ts`) used to repeat the colour codes by hand, copied from the stylesheet. That meant they could never follow a theme change, and the two copies could drift apart.
- It now points at the stylesheet's colours instead of repeating them. Nothing that uses the file had to change, and there is no longer a list to keep in sync by hand.

### 4) ScaleVault logo in the browser tab

- The tab icon was still the default Next.js logo from when the project was first created — it had never been changed.
- It is now the ScaleVault artwork (the same image used for the phone app icon).
- The image is prepared in six sizes (16, 32, 48, 96, 192 and 512 pixels) rather than shipping one large picture for the browser to shrink itself. Shrinking it in advance keeps it much sharper in the tab.
- The old default icon file had to be deleted, not just replaced. While it was still there, browsers asking for the tab icon by its usual address kept getting the old Next.js logo no matter what else was set up.
- The tab title now reads "ScaleVault — Diecast Expense Tracker", matching the name the phone app already uses.

## User Impact

- The portal can now be used in a light colour scheme — useful in a bright room or on a screen where the dark navy is hard to read.
- Nothing changes for anyone who does not touch the setting. The portal opens dark, exactly as before, until a different choice is made.
- The choice sticks, so it only has to be set once per browser.
- Browser tabs and bookmarks now show the ScaleVault car logo instead of a generic Next.js icon, which makes the portal easy to spot among many open tabs.
- Saving the portal to an iPhone or iPad home screen now uses the proper ScaleVault icon too.

## Notes for Next Time

- **Still to be checked by eye:** the theme switch was verified on the login page and by inspecting the colour values, but the pages behind login were not — nobody was signed in during the session. Worth a look at the big data tables in light mode especially: the table header dividers, the row hover shading, the column menu and filter icons, and the little magnifying glass in the filter search box.
- **Known issue, deliberately left alone:** a few pickers (the "LOV" selector used in the purchase forms) draw white rows with dark grey text on the navy background, and six loading spinners are nearly invisible for the same reason. This is an old bug, not caused by today's work, and it is unaffected either way by the new switcher. It is worth fixing on its own.
- The browser's address-bar tint is set to the dark navy for both themes. If the light theme gets heavy use it may be worth revisiting.
- The icon artwork is detailed, so at the very smallest tab size (16 pixels, on non-Retina screens) the car reads as a soft shape rather than a crisp outline. On a Retina Mac the 32-pixel version is used and looks fine. If it ever looks too muddy, cropping the artwork tighter — into the display case, dropping the outer border — would give the car more room.
