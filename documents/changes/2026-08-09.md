## What Changed

### 1) Editing a purchase into a pre-order now actually tracks it

- The Pre-order Tracker page only ever shows purchases that are linked to a "PO order" record. Adding a new purchase already knew how to create that link when you ticked "Is this a pre-order?" — but the Edit Purchase form never did. It only had an old status field (Pending / Paid / Cancelled) that updates the purchase's own row and nothing else.
- So if you saved a normal purchase and only realised afterwards it was actually a pre-order, editing it to say so quietly did nothing — the item never appeared on the tracker, with no error to explain why.
- The Edit form now has the same "Pre-order Tracking" section the Add form has: a Yes/No toggle, a search box to link the item to an existing PO order or start a new one, order details (channel, ETA, close date, source link), and a Regular/Chase/Combo variant picker. Turning it on and saving now creates the same link Add Purchase does, and the item shows up on the tracker right away.
- The old Pending/Paid/Cancelled field was left in place — it still shows as a column on the main purchase list, so removing it would have broken that display for no reason.

### 2) Collection Name field redesigned

- On Add Purchase, typing a new collection name used to make the field collapse into a button showing "+ name (new)" with a dropdown arrow — so a plain typed name ended up looking like a dropdown menu instead of a text box.
- Worse, when no existing collection matched what you typed, the box that appeared said "Close this to add as new collection" — but there was nothing to click. You had to guess that clicking elsewhere, or pressing Escape, was what "confirmed" it.
- The field is now a normal, always-visible text box. Matching collections appear in a list right underneath as you type, and if nothing matches, there's a plain "Add new collection" row you can actually tap — no more guessing.

## User Impact

- Marking an existing purchase as a pre-order after the fact now works exactly like ticking it during Add Purchase — the item appears on the Pre-order Tracker immediately.
- Typing a collection name feels like typing into a normal search field. Creating a brand-new collection is now one visible tap instead of an unlabelled "close this" trick.

## Follow-up work (same day, after first pass)

### 3) Sidebar icons switched to HugeIcons

- The sidebar (Dashboard, Collection, Purchases, Management) used the `lucide-react` icon set. The mobile app switched its bottom nav and dashboard to HugeIcons earlier today, so the web sidebar is now being moved over to match — one consistent icon style across both apps.
- All nine sidebar icons were replaced, one at a time as each was picked out: **Dashboard** (Analytics), **Collection → List** (Task Daily) and **Catalog** (Garage), **Purchases → List** (Wallet Done), **New Purchase** (Shopping Cart Add), and **Pre-order Tracker** (Delivery Delay), **Management → Brand** (Tags), **Shop** (Store Location), and **Image Import** (Image Download).
- All nine icon names were checked against the installed HugeIcons free package before use, so there was no repeat of the mobile app's earlier surprise (one icon marked "free" on the HugeIcons website that turned out not to be in the actual free package).
- The file that lists all the sidebar icons, `lib/theme/nav-config.ts`, had to be renamed to `lib/theme/nav-config.tsx` — it now contains a small bit of icon-drawing code (JSX) that a plain `.ts` file isn't allowed to hold.
- Added two new packages: `@hugeicons/react` (the icon-drawing component) and `@hugeicons/core-free-icons` (the actual icon artwork, free and open licence).
- The small "Car" icon used for the Catalog link in a couple of other places in the app was intentionally left as-is for now — it wasn't part of the list of icons to change.
